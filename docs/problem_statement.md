# Постановка задачи

## Отличие от соревнования Kaggle

Соревнование H&M Personalized Fashion Recommendations — задача товарных рекомендаций (MAP@12 по 12 товарам на
клиента). Здесь на той же истории транзакций решается другая задача: бинарный прогноз того, совершит ли недавно
покупавший клиент хотя бы одну наблюдаемую покупку в следующие 30 дней. Товары не рекомендуются.

## Единица наблюдения

Клиентский срез — пара `(customer_id, cutoff_date)`.

| Элемент | Определение |
|---|---|
| Окно истории | `[cutoff_date − 90 дней, cutoff_date)` |
| Целевое окно | `[cutoff_date, cutoff_date + 30 дней)` |
| Когорта | клиенты с ≥ 1 товарной записью в окне истории |
| target = 1 | в целевом окне есть ≥ 1 товарная запись клиента |
| target = 0 | в целевом окне нет наблюдаемых записей в этом наборе (не «вечный отток», не отсутствие покупок вне H&M) |
| Допустимость среза | `cutoff_date + 30 ≤ observation_end_exclusive` и `cutoff_date − 90 ≥ первая дата данных` |

Покупка в сам `cutoff_date` относится к целевому окну. Несколько товаров или дней в окне дают один положительный
ответ. Один клиент присутствует в нескольких срезах; разбиение только по времени.

## Признаки core (ровно три)

| Признак | Определение | Единицы |
|---|---|---|
| `purchase_days_90d` | число различных `t_dat` с ≥ 1 записью клиента в окне истории | дни |
| `avg_scaled_spend_per_purchase_day_90d` | сумма `price` записей в окне / `purchase_days_90d` | предоставленная (масштабированная) шкала цены за покупательский день; не средний чек заказа |
| `recency_days` | `cutoff_date − max(t_dat в окне)` | дни, 1…90 |

`purchase_days_90d` — не число заказов: `order_id` в источнике нет.

## Модели

| Модель | Признаки | Score |
|---|---|---|
| Recency baseline | `recency_days` | `−recency_days` (ранжирующий score, не вероятность) |
| LogisticRegression | core | `decision_function` |
| CatBoostClassifier | core | `RawFormulaVal` |
| CatBoostClassifier | extended (16 признаков) | `RawFormulaVal` |
| LogisticRegression (диагностика) | extended | `decision_function`, не участвует в выборе |

## Метрики

Главная development-метрика — AP (`sklearn.metrics.average_precision_score`). Также ROC-AUC, Precision@k и
Lift@k для долей 1/5/10% аудитории среза, `k = ceil(доля · N)`; основной бюджет CRM — top 5% (проектное
допущение, не бюджет H&M). Для вероятностных моделей — Brier score и log loss до и после калибровки.
